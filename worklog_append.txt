- Queried production /api/projects to find the actual state: project currentStage=3 (Review), but PublisherSocialMedia (stage 4) = completed and PublisherWeb (stage 4) = pending. The project was STUCK at stage 3 even though the Reviewer was done.
- Root cause analysis:
  * Frontend lock: project-detail-view.tsx checks `task.stage === project.currentStage` to determine `isCurrentStage`. Since task.stage=4 != currentStage=3, `canActOnTask=false` → padlock shown.
  * Backend stuck: The project likely got stuck due to Cloudflare Workers CPU timeout during /api/tasks PUT — the task was marked completed but the `UPDATE projects SET currentStage = ?` never ran.
  * The existing /api/projects/repair route only fixed projects where ALL tasks are completed (→ stage 5). It didn't fix projects stuck at an INTERMEDIATE stage.
- Found 10 projects stuck at stage 3 with partial stage-4 completion (PublisherSocialMedia done, PublisherWeb pending) + 3 projects stuck at stage 3 with no stage 3 (Reviewer) task at all.
- Verified the /api/tasks/route.ts stage-advance logic is correct for the NORMAL flow: `allCurrentDone = currentStageTasks.every(t => t.status === 'completed')` — only advances when ALL tasks at the current stage are done. The bug was only in the repair route, not the task completion logic.
- Fix 1 (commit c914b9b): Rewrote /api/projects/repair/route.ts to add PASS 2:
  * PASS 1 (original): projects where ALL tasks completed → currentStage = 5.
  * PASS 2 (new): projects where currentStage < 5 and all tasks at currentStage are completed → advance to the lowest stage with pending tasks.
  * Added `pass1Fixed` + `pass2Fixed` fields to the response.
  * First deployment: fixed 8 out of 10 stuck projects (the 2 remaining had no stage 3 tasks).
- Fix 2 (commit b3062f4): Handle projects with NO tasks at current stage:
  * 3 projects had currentStage=3 but no Reviewer task at all — the old logic skipped them (`currentStageTasks.length === 0 → continue`).
  * Changed the check: `allCurrentDone = currentStageTasks.length === 0 || currentStageTasks.every(...)` — treats "no tasks at current stage" as "all done" so the project can advance past the empty stage.
- Deployed both fixes to Cloudflare Workers: Version ID `1a9704a4-58be-406e-8502-c1fc8a329ea4`.
